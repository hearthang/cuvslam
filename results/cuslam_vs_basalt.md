# cuSLAM（修复版 cuVSLAM 双目+IMU + 回环后端）vs Basalt VIO：回到起点闭合误差

数据：`F:\data_set\slam` 全部 47 个 bag（8-5 … 9-29）。指标与 `basalt_closure_ratios_20260929.csv` 相同：假设首尾严格重合，闭合误差 = |p_last − p_first|（3D，imu_link 位置），比例 = 误差 / 3D 轨迹长度。完整报告（实现、改动记录、实验）：https://claude.ai/code/artifact/e07b2ae8-bbb8-4665-8fda-cf26be0c0a2f

## 结论（v10，修复版 cuVSLAM）

| 方法 | 均值 m | 中位数 m | 最大 m | 均值 % | 优于 Basalt 的 bag |
|---|---|---|---|---|---|
| Basalt VIO（双目+IMU，无回环） | 0.394 | 0.315 | 1.559 | 0.170 | — |
| **cuSLAM SLAM v10（交付，`slam_cuvslam_*.txt`）** | **0.221** | **0.143** | **1.241** | **0.096** | **37/47** |
| cuSLAM 前端（修复版，无回环） | 0.487 | 0.412 | 1.626 | — | 17/47 |
| 上一版 SLAM v8（官方 cuVSLAM、5.3 Hz 前端，已弃用） | 0.199 | 0.143 | 1.177 | — | 41/47 |
| cuVSLAM 原生 Inertial+SLAM（官方版，46 个 bag） | 52.5 | 0.194 | 1764.8 | — | 30/46 |

- SLAM 的均值、中位数、最大值都低于 Basalt。与 Basalt 轨迹刚体对齐后，偏差中位数 0.16 m（p90 0.24 m，最大 0.57 m）；路径长度比中位数 1.009（0.997–1.026）。闭合误差变小来自回环约束，而不是轨迹被压缩。
- 前端单独评测仍落后 Basalt 约 25–30%，最大误差已与 Basalt 相当。
- 跳变：47 个 bag 上的最大值都不超过 Basalt 最大跳变的 2 倍（`traj_jumps.py`）。SLAM 最大 0.093 m/步、1.49 m/s、6.6°/步、105°/s；前端最大 0.091 m/步、1.46 m/s、12.0°/步、192°/s。Basalt 最大 0.135 m/步、0.96 m/s、13.3°/步、107°/s。

## 修复版 cuVSLAM

官方 cuVSLAM v17 的双目+IMU 模式在 IMU 初始化后，每帧用“惯性 PnP”（`libs/imu/soft_inertial_pnp.cpp`）求位姿。它会引入平移误差，帧率越高越严重：6 个 bag 子集上，16 Hz 为 1.06 m，5.3 Hz 为 0.42 m。修复版（cuVSLAM 分支 `cj/inertial-fusion-experiments`，提交 `a9453d5`）在 `libs/pipelines/track_online_inertial.cpp` 加了开关 `CUVSLAM_EXP_FORCE_STEREO_PNP`：每帧改用纯视觉双目 PnP。IMU 仍用于初始化、重力和零偏估计，以及带 IMU 的关键帧 SBA。修复后 6 个 bag 子集在 16 Hz 下为 0.30 m（Basalt 0.28 m）。`run_frontend.py` 会自动设置该开关，并拒绝官方 wheel（`17.0.0+57f42cc`）。

另外处理了人工搬动：4 个 bag 中割草机被抬起（倾角 28–85°），之后 cuVSLAM 的 IMU 状态被破坏且不恢复。前端用加速度计检测离地（> 25° 进入，< 12° 持续 1 s 解除），离地期间保持位置、用陀螺积分旋转，放下后重新初始化跟踪器并用重力校平。9-22 03:57 因此从 12.9 m 降到 1.1 m。

## 复现

```bash
OUT=results/fe5 ./run_fe_all.sh 8                                        # 前端（cuvslam-dev，修复版，16 Hz）
conda run -n cuvslam python backend.py results/fe5 --jobs 14 --odom fe_in --suffix _v10
FE_DIR=results/fe5 python3 summarize_be.py _v10
conda run -n cuvslam python export_slam_traj.py                          # -> slam_cuvslam_<bag>.txt，与 vio_basalt_<bag>.txt 同目录
conda run -n cuvslam python export_frontend_traj.py results/fe5          # -> results/fe5/<tag>_frontend.txt
conda run -n cuvslam python traj_jumps.py                                # 跳变统计
```

## 说明 / 局限

- 参数（焦距修正、搬动阈值、GNC 尺度、剔除阈值等）是在这 47 个 bag 上调的，没有独立测试集。前端全量只跑了一次，而 cuVSLAM 存在运行间随机性。
- 指标假设首尾严格重合。仍有 10 个 bag Basalt 更好，最差为 9-18/05_10_37（1.24 m vs 0.31 m）。这个 bag 和 9-29/05_01_03 都是后端把误差拉大（前端分别为 0.48、0.63 m），原因尚未查明。
- 修复只是绕开了惯性 PnP，并未修好它本身。搬动处理依赖“离地后放回原处”的假设。
- 依赖 CUDA GPU，只作为桌面端参考和伪真值，不能部署到 RK3576。
